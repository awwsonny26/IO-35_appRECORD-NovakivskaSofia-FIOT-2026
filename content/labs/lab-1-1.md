## Опис предметного середовища

Онлайн-навчання стало одним із найпоширеніших способів отримання нових знань, підвищення кваліфікації та отримання практичних навичок. Через значну кількість освітніх платформ користувачам важливо швидко знаходити потрібні курси, переглядати напрями підготовки та отримувати структуровану інформацію у зручному форматі. Саме тому розробка адаптивного вебзастосунку, який забезпечує зрозумілу навігацію, логічне групування контенту та коректне відображення на різних пристроях, є доречною та практично корисною.

У межах цієї лабораторної роботи розглядається вебзастосунок StudySpace, призначений для представлення онлайн-курсів у вигляді адаптивного каталогу. Користувач повинен мати змогу переглядати категорії курсів, знайомитися з коротким описом програм, бачити інформацію про викладачів та орієнтуватися в структурі сайту незалежно від розміру екрана.

**Об’єкт дослідження:** процес взаємодії користувача з вебзастосунком для перегляду та вибору онлайн-курсів.

**Предмет дослідження:** методи проєктування предметної області та засоби реалізації адаптивного інтерфейсу вебзастосунку-каталогу курсів.

## Бізнес-логіка системи

Бізнес-логіка вебзастосунку StudySpace полягає в організації зручного доступу до каталогу онлайн-курсів. Користувач відкриває головну сторінку, знайомиться з призначенням сервісу, переходить до блоку категорій, переглядає доступні курси та отримує коротку інформацію про тематику, рівень складності, тривалість і викладача. У межах навчального проєкту особлива увага приділяється саме структурі інтерфейсу, адаптивності та зручності подання контенту.

Система має спрощену модель, достатню для демонстрації предметної області. Вона не перевантажується зайвими сутностями, але дозволяє показати основні сценарії взаємодії користувача із сайтом, побудувати Use-case діаграму, ER-діаграму та підготувати основу для подальшого розвитку проєкту в наступних лабораторних роботах.

## Функціональні вимоги

- Система повинна відображати головну сторінку з коротким описом сервісу.
- Система повинна надавати список курсів у вигляді карток.
- Система повинна групувати курси за категоріями.
- Система повинна дозволяти перегляд короткої інформації про курс.
- Система повинна містити навігаційне меню для переходу між основними блоками сторінки.
- Система повинна підтримувати адаптивне бургер-меню на малих екранах.
- Система повинна містити блок із контактною інформацією або формою звернення.
- Система повинна забезпечувати візуальний зворотний зв’язок під час взаємодії з елементами інтерфейсу.

---

## Нефункціональні вимоги

- Інтерфейс повинен коректно відображатися на комп’ютерах, планшетах і смартфонах.
- Для побудови адаптивного макета повинні використовуватися сучасні засоби CSS, зокрема Flexbox або Grid.
- Для адаптації інтерфейсу під різні розміри екранів повинні використовуватися media queries.
- Під час верстки бажано застосовувати відносні одиниці вимірювання.
- Інтерфейс повинен бути простим, зрозумілим та візуально охайним.
- Структура сторінки повинна бути семантично правильною та включати header, main і footer.
- Код повинен бути логічно розділений на HTML, CSS і JavaScript файли.

## Хід виконання

### Вибір теми та аналіз предметної області

Для виконання лабораторної роботи було обрано тему адаптивного вебзастосунку-каталогу онлайн-курсів StudySpace. Така тема є зручною для реалізації, оскільки дозволяє поєднати моделювання предметної області з розробкою сучасного адаптивного інтерфейсу. Під час аналізу предметної області було визначено, що основне призначення застосунку полягає у зручному поданні інформації про доступні курси, категорії навчання, викладачів і можливість звернення користувача через форму зворотного зв’язку.

### Формування вимог до системи

На цьому етапі було визначено функціональні та нефункціональні вимоги до вебзастосунку. Зокрема, система повинна відображати головну сторінку, список категорій, картки курсів, блок переваг, форму звернення та footer із контактною інформацією. Окрему увагу було приділено вимогам до адаптивності інтерфейсу, коректного відображення на різних типах пристроїв, використання семантичної структури сторінки та реалізації адаптивної навігації.

### Побудова Use-case та ER-діаграм

Для формалізації логіки системи було побудовано Use-case діаграму, яка відображає основні сценарії взаємодії користувачів із вебзастосунком. Також було створено ER-діаграму, що демонструє основні сутності предметної області, їх атрибути та зв’язки між ними. Це дозволило впорядкувати структуру системи ще до початку безпосередньої реалізації інтерфейсу.

### Use-case діаграма

У системі було виділено двох основних акторів: відвідувач і адміністратор. Відвідувач переглядає головну сторінку, категорії курсів, список курсів, детальну інформацію про окремий курс та може залишити заявку. Адміністратор взаємодіє із системою на рівні керування курсами, категоріями, викладачами та заявками. Така модель дозволяє відобразити основні сценарії використання системи та визначити її функціональні межі.

![Use-case діаграма](/assets/labs/lab-1-1/use-case-diagram.png)

### ER-діаграма

ER-діаграма відображає основні сутності предметної області: Category, Instructor, Course та Request. Центральною сутністю є Course, оскільки саме навколо неї будується головна логіка вебзастосунку. Кожен курс належить до певної категорії та пов’язаний з викладачем. Для фіксації звернень користувачів використовується сутність Request, яка містить контактні дані та посилання на курс.

Для реалізації вебзастосунку використано просту та зрозумілу структуру файлів. ### Реалізація стилів та адаптивності

Для стилізації вебзастосунку було використано CSS із застосуванням `Grid`, `Flexbox`, відносних одиниць вимірювання та `media queries`. Основну увагу приділено побудові адаптивної сітки, оформленню карток, кнопок і форми зворотного зв’язку, а також створенню плавних hover-ефектів. Завдяки цьому сторінка коректно відображається як на великих екранах, так і на мобільних пристроях.

```css
.hero__grid {
  display: grid;
  grid-template-columns: 1.2fr 0.8fr;
  gap: 2rem;
  align-items: center;
}

.courses__grid {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1.5rem;
}

.course-card,
.category-card,
.benefit-card {
  background: #ffffff;
  border: 1px solid #cfd7ea;
  border-radius: 1.5rem;
  padding: 1.5rem;
  transition: transform 0.3s ease, box-shadow 0.3s ease;
}

.course-card:hover,
.category-card:hover,
.benefit-card:hover {
  transform: translateY(-4px);
  box-shadow: 0 20px 40px rgba(37, 45, 65, 0.08);
}

@media (max-width: 900px) {
  .hero__grid,
  .contact__grid,
  .footer__inner {
    grid-template-columns: 1fr;
  }

  .courses__grid,
  .categories__grid,
  .benefits__grid {
    grid-template-columns: 1fr;
  }

  .nav {
    display: none;
  }

  .burger {
    display: inline-flex;
  }
}
```

### Додавання інтерактивності за допомогою JavaScript

За допомогою JavaScript було реалізовано інтерактивну поведінку адаптивного меню. Під час натискання на кнопку бургер-меню відбувається відкриття або закриття навігаційного блоку, а після вибору пункту меню навігація автоматично закривається. Це покращує зручність користування сайтом на мобільних пристроях.

```js
const burger = document.getElementById('burger');
const nav = document.getElementById('nav');

burger.addEventListener('click', () => {
  burger.classList.toggle('is-active');
  nav.classList.toggle('is-open');
});

nav.querySelectorAll('a').forEach((link) => {
  link.addEventListener('click', () => {
    burger.classList.remove('is-active');
    nav.classList.remove('is-open');
  });
});
```
